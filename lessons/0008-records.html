Lesson 8: Records

← All lessons · About 12 minutes. Builds on Lesson 7.

The one idea

A record is a class for plain data. You list the components and the compiler writes the rest.

public record UserSummary(UserId id, String email, boolean verified) {}

From Oracle: Records: the compiler generates a private final field and a public accessor per component, a canonical constructor, and equals, hashCode and toString. Records are final and immutable ("simple data carrier"). The accessor for email is email(), not getEmail().

Two records are equal when they have the same type and equal component values.

Read real code

UserSummary is the whole record: one line.

Money adds a compact constructor (no parameter list) to validate:

public Money {
    Objects.requireNonNull(amount, "amount");
    if (amount.signum() <= 0) { throw new IllegalArgumentException(...); }
    ...
    amount = amount.setScale(digits);
}

At its end, the (possibly reassigned) parameters are stored in the fields. So the last line normalises the amount before it is kept. Records can also have static methods (Money.of) and instance methods (plus).

Record or class? Money is a value: two Money of 12.50 EUR are the same thing. Expense has identity and changes, so it is a class.
