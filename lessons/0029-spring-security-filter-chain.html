Lesson 29: Spring Security, the filter chain

← All lessons · About 14 minutes. Builds on Lesson 28.

The one idea

Spring Security is a chain of servlet filters in front of your controllers. A SecurityFilterChain bean defines the filters for a set of requests, and "only the first SecurityFilterChain that matches is invoked", so chains are ordered from most specific to least (Spring Security: architecture). Inside a chain, authorizeHttpRequests lists rules and "applies only the first match"; anyRequest() goes last (authorize requests).

Read real code

SecurityConfig, whose class comment says "Deny by default":

@Bean @Order(1)
SecurityFilterChain actuatorSecurity(HttpSecurity http) {          // only actuator requests
    http.securityMatcher(EndpointRequest.toAnyEndpoint())
        .authorizeHttpRequests(a -> a.requestMatchers(EndpointRequest.to("health", "info", "prometheus")).permitAll()
                                     .anyRequest().denyAll());
    return http.build();
}

@Bean @Order(2)
SecurityFilterChain apiSecurity(HttpSecurity http, ...) {           // everything else
    http.csrf(AbstractHttpConfigurer::disable)
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(a -> {
            a.requestMatchers("/api/v1/auth/**", "/.well-known/jwks.json").permitAll();
            a.anyRequest().authenticated();
        })
        .oauth2ResourceServer(o -> o.jwt(...).authenticationEntryPoint(problems).accessDeniedHandler(problems))
        .addFilterAfter(new MdcUserFilter(), BearerTokenAuthenticationFilter.class);
    return http.build();
}
  • Two chains. Actuator requests hit chain 1 and nothing else does. All other requests fall to chain 2.
  • Allow list. Only login-related paths and the public keys are open; anyRequest().authenticated() closes everything else. A new endpoint is protected automatically.
  • Stateless bearer tokens. oauth2ResourceServer().jwt() handles requests with an Authorization: Bearer header: the signature, expiry and issuer of the JWT are validated (JWT resource server). No session; the code comment explains CSRF is off for that reason (ADR 0004 covers the cookie endpoints).
  • Same error format. ProblemSecurityHandler is both the 401 entry point and the 403 handler, so security failures also return problem+json (Lesson 25), even though no controller ran.
  • Custom filters are placed relative to a known one with addFilterAfter/addFilterBefore.
Extending: you rarely edit this file. A new /api/v1/... endpoint is authenticated by default. Only a deliberately public path needs a permitAll line, and that deserves a review.
