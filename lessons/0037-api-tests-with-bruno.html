Lesson 37: API tests with Bruno

← All lessons · About 12 minutes. Builds on Lesson 36.

The one idea

JUnit tests (Lesson 26) check code from the inside. The bruno/ collection checks the running application from the outside, the way a client sees it. Each request is one text file ending in .bru, committed to git. Bruno tests use Chai's expect, and values can be saved with bru.setVar for later requests (Bruno: tests).

Read real code

create draft.bru, shortened:

meta { name: create draft, seq: 1 }
post { url: {{host}}/teams/{{teamId}}/expenses, body: json, auth: bearer }
headers { Idempotency-Key: {{$randomUUID}} }
auth:bearer { token: {{carolToken}} }
body:json { { "money": { "amount": "12.50", "currency": "EUR" }, "category": "MEALS", ... } }

script:post-response {
  bru.setVar("draftId", res.body.id);          // for the next requests
  bru.setVar("draftEtag", res.headers["etag"]);
}
assert { res.status: eq 201   res.body.status: eq DRAFT }
tests { test("Location and ETag are set", function () { expect(res.headers["etag"]).to.match(/^"\d+"$/); }); }
  • {{host}}, {{teamId}} come from environments/local.bru; tokens are set by the 00-auth login requests.
  • assert is the short form (status, body fields); tests is JavaScript for anything more.
  • Negative tests matter as much as happy paths. create with a future date.bru asserts 400 (Lesson 25's domain rule). edit with a stale If-Match.bru sends If-Match: "999" and asserts 412 and code PRECONDITION_FAILED: the optimistic locking from @Version (Lesson 24) seen from the client.
  • Folders 00-auth to 05-security run in order and pass tokens, ids and ETags along; seq orders requests inside a folder. The README table says what each folder proves.

Run it: make up (the whole stack with demo data), then make api-test, which runs npx @usebruno/cli run --env local -r in bruno/. Use it only on local demo data, never on a shared system. (The Bruno page I read does not cover the assert block or the CLI; the repo's README and Makefile do.)

Extending: for every new endpoint add at least a happy path and one refusal (wrong role, missing field, stale ETag) to the matching folder, so the contract in openapi.yaml is proven end to end.
