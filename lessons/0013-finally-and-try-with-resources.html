Lesson 13: finally and try-with-resources

← All lessons · About 12 minutes. Builds on Lesson 10.

The one idea

Two tools for cleanup that must happen no matter how code exits.

finally runs "always ... when the try block exits", whether it finishes normally, throws, or leaves through return, continue or break. It may not run if the JVM exits meanwhile (Oracle: finally).

try {
    ...
} catch (IOException e) {
    ...
} finally {
    cleanup();
}

try-with-resources declares resources in parentheses. Anything implementing AutoCloseable is closed automatically when the block ends, normally or not, in reverse order of declaration. Oracle recommends it over a manual finally for closing, because a failing close() in finally can hide the original exception (Oracle: try-with-resources).

try (FileReader fr = new FileReader(path);
     BufferedReader br = new BufferedReader(fr)) {
    return br.readLine();
}   // br closes first, then fr

Read real code

  • ClamAvScanner.scanOnce line 65: try (Socket socket = new Socket()) { ... }. The network connection is always closed.
  • ScanReceipt.scan line 82: try (InputStream content = storage.open(...)) { ... }, plus a catch that logs and rethrows.
  • MdcUserFilter line 31: try { chain.doFilter(...) } finally { MDC.remove(KEY) }. Not a resource, but the logging context must be cleared even if the request fails. That is a job for finally.
  • ClamAvScanner line 59 combines Lesson 10's multi-catch catch (IOException | RuntimeException e) with finally { observation.stop(); }.
