Lesson 23: Services (use cases) and transactions

← All lessons · About 14 minutes. Builds on Lesson 22.

The one idea

The "service" in Ledgerly is a use case: one @Service class per action, with one public method execute. It receives a plain Command record, applies the domain rules, and returns a Result record. It never touches HTTP.

@Service
public class CreateExpense {
    public record Command(TeamId teamId, UserId claimantId, Money money, ...) {}
    public record Result(ExpenseView view, boolean replayed) {}

    private final ExpenseRepository expenses;   private final Clock clock;   ...

    CreateExpense(ExpenseRepository expenses, ..., Clock clock) { ... }   // Lesson 19

    @Transactional
    public Result execute(Command c, @Nullable String idempotencyKey) {
        access.actor(c.teamId(), c.claimantId());
        Expense expense = Expense.draft(c.teamId(), ..., clock);
        ExpenseView view = ExpenseView.of(expenses.save(expense));
        events.publishEvent(new ExpenseEvent.Created(...));
        return new Result(view, false);
    }

That is CreateExpense: check access, build the entity through the domain's factory (Lesson 7), save it, publish an event.

@Transactional

@Transactional on a method runs it in one database transaction: all writes commit together or none do. It is "merely metadata"; Spring acts on it by wrapping the bean in a proxy (Spring: @Transactional). Three rules to remember:

  • Rollback: "Any RuntimeException or Error triggers rollback"; a checked Exception does not by default. Lesson 10 pays off: every ExpenseException is a RuntimeException, so a refused rule undoes the whole use case.
  • readOnly: @Transactional(readOnly = true) marks queries; the repo uses it in DownloadReceipt, ListReceipts, ReceiptChecksImpl.
  • Self-invocation: in proxy mode only calls coming in through the proxy count. A method calling another @Transactional method of the same class gets no new transaction. Keep annotated methods as the public entry point, as the use cases do.
ScanReceipt uses tx.execute(s -> ...), a TransactionTemplate with a lambda (Lesson 17), to run only part of a method in a transaction.
