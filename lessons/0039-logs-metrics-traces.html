Lesson 39: Logs, metrics and traces

← All lessons · About 14 minutes. Builds on Lesson 38.

The one idea

When something breaks in production you have three clues: logs (what happened), metrics (how much, how often), traces (where time went across calls). Ledgerly sends all three to the Grafana stack in compose.

Logs

  • Production logs are structured JSON (logging.structured.format.console: ecs); the local profile switches to readable text (Lesson 36).
  • The MDC (a per-thread map that logging adds to every line) carries context: MdcUserFilter puts the caller's userId (never the email) on every line of the request, and MdcTeamFilter the teamId from the URL. Both use try { chain.doFilter(...) } finally { MDC.remove(KEY) } (Lesson 13) so the context never leaks to the next request on that thread. The filters are registered in the security chain (Lesson 29).
  • Log messages in the code avoid secrets and personal data (e.getClass().getSimpleName() instead of messages); LogHygieneTest checks it.

Metrics

Actuator exposes operational endpoints; here only health,info,prometheus, on port 8081, separate from the API port (Spring Boot: actuator endpoints). Health probes are served at /actuator/health/liveness and /readiness. Spring Boot auto-configures a MeterRegistry that you can inject; /actuator/prometheus serves a Prometheus scrape (Spring Boot: metrics).

// ScanReceipt.java
metrics.counter("ledgerly.receipts.quarantined").increment();     // one more infected file
// TransitionExpense counts transitions by action tag; MetricsTest checks "submit" +1, a refused approve not counted

Traces and observations

An Observation is one instrumented unit of work; handlers turn one instrumentation into a timer and a trace span. Key values are low cardinality (bounded, fine for metrics) or high cardinality (unbounded, for traces) (Micrometer: introduction, instrumenting).

// ClamAvScanner.scan
Observation observation = Observation.createNotStarted("ledgerly.clamav.scan", observations).start();
try (Observation.Scope scope = observation.openScope()) {
    Result result = scanOnce(content);
    observation.lowCardinalityKeyValue("outcome", result instanceof Result.Clean ? "clean" : "infected");
    return result;
} catch (IOException | RuntimeException e) {
    observation.lowCardinalityKeyValue("outcome", "error");  observation.error(e);  throw e;
} finally { observation.stop(); }

Lessons 10, 13 and 16 in one method: try-with-resources for the scope, multi-catch, instanceof pattern, finally to stop. The comment says it records "the outcome, never the content". management.tracing.sampling.probability: 1.0 traces every request, and compose sets the OTLP endpoint so traces reach lgtm; Grafana is at http://localhost:3000 (admin/admin). (The README notes that traces reaching Grafana were not verified in the learning log.)

Extending: log with ids, not values; count business events with a counter and low-cardinality tags (action, outcome), never ids or emails as tags.
