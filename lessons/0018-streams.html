Lesson 18: Streams

← All lessons · About 12 minutes. Builds on Lesson 17.

The one idea

A stream carries values from a source through a pipeline of operations: source, then intermediate operations (each returns a new stream), then one terminal operation that produces the result (Oracle: Streams).

roster.stream()                         // source
      .filter(p -> p.isMale())          // intermediate
      .mapToInt(Person::getAge)         // intermediate
      .average()                        // terminal

Oracle: "unlike a collection, it is not a data structure that stores elements". Iteration is internal: you say what to do, the JDK decides how. The operations take the lambdas and method references from Lesson 17.

Read real code

// ExpenseDeletedCleanup.java line 38
List<String> keys = found.stream().map(Receipt::storageKey).toList();

// BatchCreateExpenses.java, Result.created()
return results.stream().filter(r -> r.id() != null).count();

// BatchCreateExpenses.java line 83
if (atomic && problems.stream().anyMatch(p -> p != null)) { ... }
  • First: take each receipt, map it to its storage key, collect a list. The same job as a for loop (Lesson 3) with an add, in one line. (toList() and anyMatch are used in the repo; Oracle's page covers filter, mapToInt and average.)
  • Second: keep results that have an id, then count them.
  • Third: is any problem non-null? Stops at the first hit.
Loops are fine too. Streams shine for "filter, transform, collect" and are not always clearer. The repo mixes both.
