Lesson 1: Declaring variables

← All lessons · About 10 minutes. Mission: read Java backend code fluently, using Ledgerly as the text.

The one idea

Java is statically typed: every variable is declared with a type, written before the name.

Type name = value;

Read real code

Open Money.java. Lines 28 to 39:

int digits = currency.getDefaultFractionDigits();   // line 28
if (digits < 0) {                                    // line 29
    throw new IllegalArgumentException("Not a monetary currency: " + currency);
}
...
amount = amount.setScale(digits);                    // line 39
  • int is the type, digits the name, and the right-hand side computes the value.
  • digits lives inside a constructor, so it is a local variable. Java has no keyword for that; location decides. Oracle: "There is no special keyword designating a variable as local" (Variables).
  • amount and currency are parameters of the record, with types BigDecimal and Currency.

Primitives vs. everything else

Java has 8 primitive types (byte short int long float double boolean char), all lowercase. int is one. String, BigDecimal and Currency are classes: capitalised, and they can be null. Primitives cannot (Primitive Data Types).

Why does Money use BigDecimal and not double? Oracle says float should not be used for precise values such as currency; double has the same binary-fraction problem.

Naming

camelCase for variables, UPPER_SNAKE for constants, PascalCase for classes. Names cannot start with a digit or be a keyword.
