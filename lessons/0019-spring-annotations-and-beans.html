Lesson 19: Spring annotations and beans

← All lessons · About 12 minutes. Builds on Lesson 18.

The one idea

An annotation (@Something) is metadata written on a class, method or field. Spring reads them. A class marked @Component is a stereotype that Spring finds by component scanning and manages as a bean: Spring creates the object for you. @Service, @Repository and @Controller are specialisations of @Component for the service, persistence and web layers; @RestController combines @Controller and @ResponseBody (Spring: Classpath Scanning).

  • The default bean name is the uncapitalised class name (SimpleMovieLister becomes simpleMovieLister).
  • The default scope is singleton: one shared instance.
  • Constructor injection: the constructor lists what the class needs; Spring supplies the arguments. The docs' own example has a constructor taking MovieFinder and no further annotation. Fields can be final (Spring: Annotation-based configuration).

  • The Lesson 7 shape: private final fields, a constructor assigning them with this.x = x. The constructor is the dependency list.
  • The fields are mostly interfaces (ExpensesFacade, Lesson 11). The class never calls new on them.
  • ReceiptsController is @RestController with @RequestMapping("/api/v1") and takes the use cases in its constructor. ScanReceipt is a plain @Component.
  • Other annotations here (@Transactional, @Async, @Override) are for later; the idea is the same: metadata that the framework acts on.
