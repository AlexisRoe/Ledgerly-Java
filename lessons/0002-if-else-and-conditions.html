Lesson 2: if, else and conditions

← All lessons · About 10 minutes. Builds on Lesson 1.

The one idea

An if needs a boolean condition in parentheses and a block in braces. Chain more paths with else if and else. The first branch whose condition is true runs; the rest are skipped (Oracle: if-then-else).

if (digits < 0) {
    ...
} else if (digits == 0) {
    ...
} else {
    ...
}

Oracle notes braces are optional for one statement, but omitting them makes code brittle when a second statement is added later. This repo always uses braces.

Read real code

In ProductionEnvironmentCheck.java (about line 50):

if (value == null || value.isBlank()) {
    missing.add(property);
}
  • == compares, = assigns. Oracle: "you must use '==', not '=', when testing if two primitive values are equal". There is no === as in JavaScript.
  • || (or) and && (and) are short-circuit: "the second operand is evaluated only if needed" (Oracle: operators). If value is null, the left side is true, so value.isBlank() never runs. Swapped, a null would crash it.

Another one, in ListExpenses.java, method parseSort:

if (field == SortField.AMOUNT && !hasCurrencyFilter) {
    throw new InvalidRequest("sort", "Sorting by amount needs a currency filter");
}

! negates a boolean. This is a guard clause: check the bad case first, throw, and keep the rest of the method flat.

Oracle also covers the ternary cond ? a : b, shorthand for if-else that returns a value. BatchCreateExpenses uses valid.isEmpty() ? List.of() : facade.createDrafts(...).
