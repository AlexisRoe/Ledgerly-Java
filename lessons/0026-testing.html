Lesson 26: Testing

← All lessons · About 14 minutes. Builds on Lesson 25.

The one idea

Tests are classes whose @Test methods the build runs (make test or make verify). A JUnit test method must not be private or abstract and must not return a value; @BeforeEach/@AfterEach run around each test (JUnit: test classes and methods).

JUnit ships assertEquals and assertThrows; the JUnit team recommends third-party assertion libraries such as AssertJ (JUnit: assertions), which this repo uses: assertThat(x).isEqualTo(y), assertThatThrownBy(...).

A unit test

// MoneyTest.java
class MoneyTest {
    @ParameterizedTest
    @ValueSource(strings = {"0", "0.00", "-1", "-0.01"})
    void rejectsZeroAndNegativeAmounts(String amount) {
        assertThatThrownBy(() -> Money.of(amount, "EUR")).isInstanceOf(IllegalArgumentException.class);
    }

    @Test
    void equalsAndHashCodeIgnoreInputScale() {
        var a = Money.of("10.0", "EUR");
        var b = Money.of("10.00", "EUR");
        assertThat(a).isEqualTo(b).hasSameHashCodeAs(b);
    }
}

MoneyTest needs no Spring: just Lesson 8's record. @ValueSource feeds each value to the method in turn (JUnit: parameterized tests). The lambda in assertThatThrownBy is Lesson 17. Test names read as sentences: what the code should do.

An integration test

// TeamsApiTest.java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT, properties = "management.server.port=0")
@Import(TestcontainersConfiguration.class)
class TeamsApiTest {
    @LocalServerPort int port;
    @Autowired JdbcClient jdbc;
    RestTestClient client;

    @BeforeEach
    void setUp() { client = RestTestClient.bindToServer().baseUrl("http://localhost:" + port).build(); ... }

@SpringBootTest "loads the full application context"; the default web environment is a mock one where embedded servers are not started, while RANDOM_PORT starts a real server on a free port (Spring Boot: testing). The test then calls the real HTTP API with RestTestClient. The @Import brings a Testcontainers configuration: a real Postgres in Docker, which is why make test needs Docker running. @Autowired lets the test ask Spring for beans.
