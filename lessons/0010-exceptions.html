Lesson 10: Exceptions

← All lessons · About 12 minutes. Builds on Lesson 9.

The one idea

An exception is an event that disrupts normal flow. Code throws an exception object; the runtime searches the call stack, caller after caller, for a matching handler (Oracle: What is an exception?).

try {
    ...
} catch (IOException e) {
    ...
}

A catch matches when the thrown object can be assigned to its parameter type. One catch can list several types with | (Oracle: catching).

Checked vs. unchecked

Checked exceptions must be caught or declared by the compiler's rules. Unchecked ones (RuntimeException, Error and subclasses) need not be. Oracle's guideline: "If a client can reasonably be expected to recover from an exception, make it a checked exception. If a client cannot do anything to recover from the exception, make it an unchecked exception." (Oracle: unchecked exceptions)

  • throw ends the method at once; the caller (or a handler further up) takes over. Every guard clause you met in Lesson 2 does this.
  • Every domain refusal extends ExpenseException, which extends RuntimeException: unchecked, because a caller cannot meaningfully recover from, say, an illegal state change.
  • The last snippet translates: SHA-256 is always available, so the checked exception "cannot happen" and is turned into an unchecked one.
