Lesson 38: Docker Compose and CI

← All lessons · About 14 minutes. Builds on Lesson 37.

The one idea

Docker Compose describes an application as services (each a container from an image), with networks and volumes for connectivity and persistent data (Docker: Compose model). compose.yaml runs everything the app depends on locally.

ServiceWhy
postgresthe database (Lesson 24)
seaweedfsS3-compatible storage for receipts and imports
clamavthe malware scanner (Lesson 11, 34)
lgtmGrafana stack that receives logs, metrics and traces (Lesson 39)
keycloakoptional external login (keycloak profile)
appLedgerly itself, only with the compose profile app
  • Every port is published as 127.0.0.1:PORT:PORT: reachable from your machine only, because these services have development passwords or none. Images are pinned by digest, since a tag can be moved to different content (local-hardening.md).
  • The app container gets its settings from environment variables (Lesson 36) and is locked down: read_only: true, cap_drop: ALL, no-new-privileges. depends_on with condition: service_healthy waits for Postgres' healthcheck before starting the app.
  • Makefile wraps it: make deps (dependencies only, for running the app from your IDE), make up (image, then everything), make down (keep data), make reset (-v: also delete the data), make logs, make ps. make image builds the container with spring-boot:build-image, so there is no Dockerfile to maintain.

CI: GitHub Actions

A workflow's on picks the triggers; jobs run in parallel by default and needs orders them; concurrency limits runs per group and cancel-in-progress drops superseded ones; permissions restricts the GITHUB_TOKEN to least privilege (GitHub: workflow syntax). ci.yml runs on every pull request to main and on pushes to it:

JobRuns
verify./mvnw -B verify: all tests (Testcontainers needs Docker, which the runner has), Spotless formatting, NullAway
openapi-lintlints api/openapi.yaml (the contract of Lesson 22)
format-configPrettier on YAML and JSON
gitleaksscans for committed secrets
imagebuilds the container image

Supply-chain care is visible: third-party actions are pinned to a commit hash ("a tag can be moved to different code after the fact"), the token is read-only, npm install scripts are disabled. Locally, make verify runs what verify runs, so run it before you push.

Extending: a change is not done until CI is green. Failing format-config is fixed by make format; a failing verify uploads the surefire reports as an artifact.
