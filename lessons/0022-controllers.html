Lesson 22: Controllers

← All lessons · About 14 minutes. Builds on Lesson 21.

The one idea

A controller maps HTTP requests to Java methods. @RestController is @Controller plus @ResponseBody: return values are written to the response body (Spring: controllers).

@RestController
@RequestMapping(path = "/pets", produces = "application/json")
public class PetController {
    @GetMapping("/{petId}")
    public Pet getPet(@PathVariable Long petId) { ... }

    @PostMapping(path = "/{ownerId}/pets", consumes = "application/json")
    @ResponseStatus(HttpStatus.CREATED)
    public void addPet(@PathVariable Long ownerId, @RequestBody Pet pet) { ... }
}
  • @RequestMapping sets what the class shares; @GetMapping, @PostMapping, @PutMapping, @DeleteMapping, @PatchMapping map one HTTP method (Spring: request mapping). {petId} captures a path segment.
  • Arguments: @PathVariable (URI template variable), @RequestParam (query parameter), @RequestBody (the body, converted to the declared type), @RequestHeader (Spring: arguments).
  • Return ResponseEntity<T> when you control status, headers and body (Spring: return values).

The Ledgerly twist: contract first

You will not find @PostMapping on ExpensesController. The API is described in api/openapi.yaml; the build (openapi-generator, see pom.xml) generates an interface ExpensesApi into target/generated-sources/ with all the mapping and validation annotations. The controller implements it (Lesson 11) and @Overrides each method:

// generated: ExpensesApi (do not edit)
@RequestMapping(method = RequestMethod.POST, value = "/teams/{teamId}/expenses",
    produces = { "application/json", "application/problem+json" },
    consumes = { "application/json" })
ResponseEntity<ExpenseResponse> createExpense(
    @PathVariable("teamId") UUID teamId,
    @Valid @RequestBody CreateExpenseRequest createExpenseRequest, ...);

// written by hand: ExpensesController
@RestController @RequestMapping("/api/v1")
class ExpensesController implements ExpensesApi {
    @Override
    public ResponseEntity<ExpenseResponse> createExpense(UUID teamId, CreateExpenseRequest request, @Nullable String idempotencyKey) {
        var command = new CreateExpense.Command(new TeamId(teamId), currentUser.id(), ...);
        var result = create.execute(command, idempotencyKey);
        return ResponseEntity.created(location).eTag(etag(view)).body(ExpenseMapper.toResponse(view));
    }

The method does three things: turn the request into a Command, call one use case, turn the answer into a response with 201 Created, a Location and an ETag. To add an endpoint: edit the contract, build, then implement the new method.
