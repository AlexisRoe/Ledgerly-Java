Lesson 24: Entities, repositories and migrations

← All lessons · About 14 minutes. Builds on Lesson 23.

The one idea

An entity is a class mapped to a table; a repository is an interface Spring turns into database code. The entity needs @Entity, an identifier (@Id or @EmbeddedId), and "a non-private no-argument constructor" (Hibernate). @Version adds optimistic locking.

@Entity @Table(name = "expenses")
public class Expense {
    @EmbeddedId private ExpenseId id;          // primary key (a record)
    @Embedded private Money money;             // Lesson 8: amount + currency columns
    @Enumerated(EnumType.STRING) private ExpenseStatus status;
    @Version private long version;             // changes on every update

    /** For JPA only. */
    protected Expense() {}                     // the required no-arg constructor
}

That is why Expense has an empty protected constructor next to its private one and its draft factory (Lesson 7).

Repositories

A repository "must extend Repository and be typed to the domain class and an ID type"; you declare methods and Spring supplies the implementation (Spring Data: repositories). Derived queries build the query from the method name: findBy + properties joined with And/Or (Spring Data: query methods). Single results come back as Optional (Lesson 14); paging takes a Pageable.

public interface ExpenseRepository extends Repository<Expense, ExpenseId> {
    Optional<Expense> findByTeamIdAndId(TeamId teamId, ExpenseId id);  // where team_id = ? and id = ?
    Expense save(Expense expense);                                     // persist or merge
    void delete(Expense expense);
    Page<Expense> findAll(Specification<Expense> spec, Pageable pageable);
}

save "persists or merges" depending on whether the entity is new (Spring Data: persisting entities). The repo's own comment explains extends Repository instead of JpaRepository: with no inherited findById, a query that is not scoped to a team cannot be written. Security by construction.

The database side: Flyway

Tables are created by versioned scripts in src/main/resources/db/migration, named V<VERSION>__<NAME>.sql, which Flyway runs at startup (Spring Boot: Flyway). V1__expenses.sql defines expenses. The config sets ddl-auto: validate, so Hibernate checks at startup that entity and tables match; a mismatch stops the app. Changing an entity field therefore means a new migration (Lesson 28).
