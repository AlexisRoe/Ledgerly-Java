Lesson 14: Optional

← All lessons · About 12 minutes. Builds on Lesson 13.

The one idea

Optional<T> is a container that holds a non-null value or is empty. Oracle's API note: it is "primarily intended for use as a method return type where there is a clear need to represent 'no result'" (Optional API). A method that may find nothing returns Optional instead of null, so the caller cannot forget the "nothing" case.

MethodDoes
Optional.of(v)wraps a non-null value; null throws NullPointerException
ofNullable(v)empty if v is null
isPresent() / isEmpty()tests for a value
ifPresent(action)runs the action only if a value exists
map(f)transforms the value if present; otherwise stays empty
orElse(other)the value, or other
orElseThrow()the value, or NoSuchElementException; preferred over get()
The lambdas (x -> ...) and Type::method forms are explained in Lesson 17. For now read them as "do this with the value".

Read real code

// Login.java line 68
Optional<User> found = users.findByEmail(normalised);
if (found.isEmpty()) { ... throw new Unauthenticated(); }

// IdentityFacade.java line 14
return find(id).map(UserSummary::verified).orElse(false);

// DownloadReceipt.java line 46
var receipt = receipts.findByIdAndTeamIdAndExpenseId(...)
        .filter(r -> r.isDownloadable())
        .orElseThrow(NotFound::new);
  • A repository method returns Optional<User>: maybe the email is unknown. Login checks isEmpty().
  • IdentityFacade: if there is a user, take its verified flag; if not, false. One line, no null check.
  • DownloadReceipt: no receipt, or not downloadable, gives a 404 (NotFound). (filter keeps the value only if the test passes; read from this code, not from the Oracle page.)
