Lesson 11: Interfaces

← All lessons · About 12 minutes. Builds on Lesson 10.

The one idea

An interface is a contract: it lists method signatures, no bodies. It cannot be instantiated, only implemented by classes, which must supply a body for every method (Oracle: Interfaces). Code that uses the interface depends only on the signatures, so implementations can be swapped.

public interface OperateCar { int signalTurn(...); }
public class OperateBMW760i implements OperateCar { public int signalTurn(...) { ... } }

Read real code

// expenses/ReceiptChecks.java
public interface ReceiptChecks {
    ReceiptSummary summaryFor(ExpenseId expenseId);
}

// receipts/internal/application/ReceiptChecksImpl.java
class ReceiptChecksImpl implements ReceiptChecks {
    @Override
    public ReceiptSummary summaryFor(ExpenseId expenseId) { ... }
}
  • ReceiptChecks has no body. ReceiptChecksImpl implements it. @Override marks a method that fulfils the contract.
  • Its comment explains the design: expenses owns the interface and receipts implements it, so the dependency points from receipts to expenses (ADR 0002). Expense.submit only knows the interface; it does not know receipts exists.
  • The same pattern: ClamAvScanner implements MalwareScanner. A test can supply a different scanner with no virus engine.
  • ExpensesFacade is an interface too: the public front door of a module.

This is also why Lesson 9 declared List<...> valid = new ArrayList<>(): the variable holds the contract, the object is one implementation.

Check yourself

What must ReceiptChecksImpl do, since it implements ReceiptChecks?

Can you write new ReceiptChecks()?

Why does expenses define ReceiptChecks while receipts implements it?
